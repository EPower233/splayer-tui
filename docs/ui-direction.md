# SPlayer 风格 TUI：界面方向

状态：**方向已确认（2026-11-08）**，细节待定。样稿见同目录 [mockup.html](mockup.html)（浏览器打开，可切换主界面 / 全屏播放页 / 换歌看封面取色）。

## 一句话

一个在终端里跑的音乐播放器：**布局和手感像 SPlayer，长相和交互是 TUI 的**。

**这里说的 SPlayer 一律指 SPlayer-Next**（2026-11-08 澄清）。界面、按钮位置、默认值、快捷键都照 SPlayer-Next 的源码。中间有一轮误照了旧版 SPlayer v3.1.1 的截图，已经全部改回来。

## 页面（照 SPlayer-Next 源码）

- **首页**（`src/pages/Home.vue`）：
  - 问候语加一句副标题，右边是本周时长 / 新增收藏 / 连续收听三个数字；
  - 推荐卡：封面、标签、标题、说明，`▷ 立即播放`、`+ 添加到队列`，右边是前 5 首预览；
  - 四个快捷入口：试试手气、每日推荐、心动模式、私人 FM；
  - 继续聆听（歌曲卡，带播放次数）；
  - 专属歌单、雷达歌单、歌手推荐、新碟上架（封面网格）。
- **歌单页**（`src/pages/Collection.vue`）：
  - 封面；来源和类型小标签（在线 / 歌单）、标题、简介 `›`；
  - 创建者、歌曲数、总时长、日期；
  - `▷ 播放全部`、`♥ 收藏 / 取消收藏`、`⋯`，右边是页内搜索框；
  - 歌曲行带缩略图：第二行是标签和歌手，右边是 ♥ / ♡ 和时长。
- **全屏播放页**：见下面第 3 条。
- **设置页**（`src/components/settings/`）：
  - 左边是"设置 / 调整您的专属配置"、搜索框和分类；
  - 右边按"▌分组标题"列设置项，Next 的分组标题前面就有一条主题色竖条；
  - 每项是名称、说明，控件靠右。
  - 终端版先只显示有功能的分类；外部歌词、AI 集成、媒体源、下载、插件等对应功能做了再出现。
- **用户菜单**（`NavUser.vue`）：头像、昵称、歌单 / 专辑 / 艺术家数量、退出登录。
- 首页各区块的标题照 Next：粗体标题加一行暗色副标题，不带竖条。

## 已确认的原则

1. **布局照搬 SPlayer**：左侧栏 + 顶栏搜索 + 中间内容 + 底部播放栏 + 全屏播放页。用过 SPlayer 的人不用改习惯。
   - 侧栏照 Next 的默认两组（`DEFAULT_SIDEBAR_NAV_GROUPS`）：
     - 第一组：首页、音乐库、艺术家、专辑、文件夹、统计；
     - 第二组：我喜欢的音乐、我的收藏、我的云盘、下载管理（默认关）、媒体源、播放历史；
     - 下面是我的歌单（本地 / 在线切换、`+`）和收藏的歌单。
   - 功能还没做的项（比如本地曲库那一组）在 v0.1 里先不显示。
2. **结构不靠底色，也不用框**（2026-11-08 修订，起因：很多终端经过 ricing 是半透明的，铺底色要么被壁纸冲淡，要么变成一块块不透明的色块）：
   - 线只用来分组，不围成框。线和线不相交，不用 `├ ┼ ┴` 这类接头字符。能带信息的线就让它带信息。
     - 竖线 `│`：侧栏和内容之间，同时充当侧栏滚动条（滑块那段用 `┃`）。
     - 横线有三种：
       - 侧栏分组线：`─`，两端缩进，不碰竖线（同 SPlayer）。要占一行，但侧栏行数有富余。
       - 歌曲行之间：用下划线属性画（SGR 4 加 SGR 58 设下划线颜色），不占行。终端不支持下划线颜色就不画，因为默认颜色的下划线太重。
       - 播放栏顶边：单独一行 `▁`（下八分之一方块），紧贴播放栏，同时充当进度条。
   - 其余靠留白和对齐：组标题用暗色，内容区没有表格线。
   - 当前行用左侧强调色 `▌` 加粗体标出，不铺底色；按键提示是强调色的键名加暗色说明，不做成色块。
   - 两种底色模式：**透明**（默认，从不画默认背景）和**实底**（在同样的结构上加 SPlayer 式的面板色阶、选中行色带）。样稿右上角可以切换。
   - SPlayer 本身也是这个思路：侧栏边一条细分隔线，播放栏顶上是进度条。
3. **按钮照 SPlayer 摆，按键只写在按钮旁边**。不设底部提示栏（2026-11-08 去掉：和按钮旁的提示重复，像临时贴上去的手册），也不为了放按键而新造 SPlayer 没有的按钮栏。所有按键提示统一用暗色，不抢内容的注意力。
   - **键位和防冲突规矩见 [keymap.md](keymap.md)**：Next 有默认快捷键的照抄，没有的才新增；每一屏都要过冲突检查。
   - **主界面顶栏**（Next 的 NavHeader）：`‹ ⌥←`、`› ⌥→`、搜索框 `^F`、头像菜单 `^U`、设置 `^,`。窗口按钮归终端管，不画。
   - **播放栏**（Next 的 PlayerBar）：
     - 左边：封面（`^⏎` 打开全屏页），然后是标题、`♥ ^L`、`⋯ ^G`（当前歌曲菜单）；
     - 中间：`⇄ ^S  |◁ ^←  ‖ ␣  ▷| ^→  ⟳ ^R`，键写在按钮正下方；私人 FM 时第一个按钮变成"不喜欢"，键还是 `^S`；
     - 右边：时间（下面是 `⇧←` `⇧→`）、音质 `^K`、音量 `^↑↓`、播放列表 `^P`、`⋮ ^E`（均衡器、播放速度、AB 循环、定时关闭）。
     - Next 播放栏上的字幕按钮是开关桌面歌词的，终端里没有桌面歌词，所以不放。
   - **全屏播放页**（Next 的经典布局）：
     - 顶栏：左边 `❝ v` 歌词开关，右边 `▦ b` 布局。Next 的全屏按钮归终端管，不画。
     - 左边：封面，下面是歌名、副标题、标签、歌手、专辑。
     - 右边：歌词，每句是原文、翻译、音译三行。
     - 歌词右侧一列（Next 的 LyricActions）：`⧉ c` 复制、`+ =` 提前、当前偏移、`− -` 延后、`⚙ o` 歌词设置。
     - 底栏（Next 的 PlayerBottomBar）：
       - 左边：`⌄ ^Esc`、`♥ ^L`、`💬 ^T`、`⊕ ^O`；
       - 中间：播放控制，进度条在按钮下方，两端是 `⇧←` `⇧→`；
       - 右边：音质、音量、播放列表、`⋮`。
   - **逐字、翻译、音译这些开关不占顶栏**：它们在 `⚙ o` 打开的歌词设置弹窗里，`w` `t` `r` 写在各自的开关旁边。
   - **列表**：光标所在那一行的右侧，显示这一行能做的事（`⏎ 播放  a 下一首  f 喜欢  m 菜单`），只在光标那一行出现。
   - **侧栏**：前 10 项右侧标 `1`–`9`、`0`，按数字直接跳转。
   - **通用操作**：没有对应按钮的（移动、`Tab` 切换焦点）不常驻提示；完整键位表按 `?` 打开。
4. **封面并进内容**：歌单页头部是"封面 + 信息 + 操作"（同 SPlayer 歌单页），播放栏左侧放缩略图；不单开封面栏。
5. **全屏播放页填满**：封面在左，歌词在右占满整高；带翻译；当前句逐字填色（默认开，设置里和歌词设置弹窗的 `w` 键都能关，关掉就整句高亮），其余越远越淡；频谱沉到底部全宽当氛围。（流动背景已去掉。）
6. **主题跟封面走**：当前歌曲封面取色生成整套配色（SPlayer 的自适应主题）。

## 终端里怎么画线（2026-11-08 实测）

- 终端只有字符格，线就是字符：盒绘字符（U+2500–257F，如 `│ ─ ┃ ━`）和方块字符（U+2580–259F，如 `▁ ▔ ▏ ▕ ▌`）。lazygit、btop、tmux 的边框都是这么画的。
- 现代终端（kitty、WezTerm、Alacritty、foot、Ghostty、Windows Terminal、VS Code）自己画这些字符，不用字体，所以相邻格子无缝衔接，行距调大也能接上。老终端用字体里的字形：实测行距 1.2 时 `▏ ▕` 会断成虚线，`▁` 也不再贴着格子底部；`│ ─` 这次没断，但这取决于字体。
- 结论：竖线和分组线用盒绘字符 `│ ─`（最稳）。进度条用 `▁` 或 `━` 都行，水平方向总能接上，`▁` 只是上下位置可能偏一点。
- 代价：每条线占一整行或一整列。下划线属性例外，不占格。xterm.js 里实测普通、彩色、点线、虚线、波浪下划线都能显示；上划线在 DOM 渲染下没显示，所以不用上划线。
- 模糊宽度：`│ ─ ━ ▁ ▌ ♥ ♡ … ●` 都属于 East Asian Ambiguous，中文环境下有的终端设置会把它们当成 2 格，整列就会错位。应用自带的终端面板里实测都是 1 格。程序要提供 `ambiguous_width = 1 | 2` 配置，或者启动时用光标位置查询（`CSI 6n`）自动测出来。
- 测试工具：[`tools/line-test.sh`](../tools/line-test.sh)，在任意终端里 `bash tools/line-test.sh` 就能看效果并测宽度；[`line-test.html`](line-test.html) 是两种渲染方式的对比（重新生成见 `tools/line-test.template.html`）。

## 终端档位（2026-11-08 决定）

做成一个选项 `terminal_profile`，**先只做「现代」，「兼容」搁置，以后再补**。

| | 现代（默认，先做） | 兼容（搁置） |
|---|---|---|
| 适用 | kitty、WezTerm、Alacritty、foot、Ghostty、Windows Terminal、VS Code | 线条字符靠字体画的老终端、不支持真彩色的终端 |
| 颜色 | 真彩色：封面取色 | 256 色 |
| 线 | `│ ─` 分隔，`▁` 进度条，滑块用 `┃` | 只用 `│ ─`；进度条改成行中间的 `━─` |
| 歌曲行分隔 | 彩色下划线 | 不画 |
| 封面 | kitty / iTerm2 / sixel 显示真图，否则半格像素块 | 半格像素块 |

**两条约束**：
- 写代码时，档位之间的差异全部集中在一个「终端能力」结构里，界面代码只读这个结构，不自己判断是什么终端。以后补兼容档位，只是给这个结构加一套取值，不用到处改。
- 模糊宽度（`ambiguous_width`）不归档位管，单独配置：现代终端里 iTerm2 之类也能把它设成 2 格。

## 图标与 emoji（2026-11-08 提议，待确认）

**怎么选**：
- **身份、状态、导航 → 图标，可以用 emoji**：账号 VIP 用 👑，侧栏导航图标，心动模式 💓。
- **条件、属性、需要读和比较的 → 文字标签**：歌曲行的 `VIP`（要会员才能听）、`SQ` / `Hi-Res` / `原` / `MV`、播放栏的 `无损`。同一个"VIP"，是身份就用皇冠，是条件就写字。
- **要跟主题变色、或者靠颜色表示开关的 → 单色字形，不用 emoji**：行内的 ♥/♡、播放控制、进度条。emoji 是彩色位图，没法改颜色，也就没法用颜色区分"已喜欢/未喜欢"。

**emoji 的技术限制**（不守这几条，列就对不齐）：
- 只用默认就是 emoji 样式的单个码位（Unicode `Emoji_Presentation=Yes`，例如 👑 🏠 🎵 📻 🎧 ⭐ 📁 🕘），它们在各家终端里都占 2 格。
- 不用要靠 `U+FE0F` 才变成 emoji 的字符（❤️ ☁️ ⚙️ 🎙️）。终端和宽度库对它们是 1 格还是 2 格意见不一，最容易错位。云盘因此用了 ⛅ 而不是 ☁️。
- 不用 ZWJ 组合（👨‍💻）、肤色修饰、国旗。

**三套图标，可切换**：每个语义图标在代码里是一个枚举，渲染时按当前图标集查表：
1. Nerd Font：单色、跟主题变色，最协调，但要装字体；
2. emoji：不用装字体（Windows Terminal、macOS 自带），彩色；
3. 纯 Unicode：最后兜底。

终端没法告诉程序装了哪些字体，所以图标集只能是配置项。首次启动时可以显示一行测试字符，让用户选能正常显示的那套。样稿里的"图标"按钮可以对比 emoji 和纯符号两套。

## 背景结论（来自对 SPlayer-Next 的分析）

- SPlayer-Next = Electron + Vue 3，约 10.5 万行 TS/Vue + 2.1 万行 Rust，AGPL-3.0。
- 可直接复用：`native/audio-engine`（NAPI 只在 `src/bindings/`，其余是纯 Rust）。要改：`native/media-ctrl`（NAPI 渗进各平台实现）。
- 要重写：`electron/main/apis/{netease,qqmusic,kugou}`、流媒体、曲库、下载；渲染进程里的队列编排（`src/core/player`、`src/stores/queue.ts`）。
- 自带的外部 API（`electron/main/server/`）只有播放控制和状态读取，没有搜索/歌单/点播，做不了独立 TUI 的后端。
- 路线：先抽无 Electron 的 Rust 核心 → TUI 作为第一个前端 → GUI（GPUI 或 Flutter）以后再定。
- 派生自 SPlayer 代码的项目必须用 AGPL-3.0。
