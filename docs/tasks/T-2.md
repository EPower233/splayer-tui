## 结论

**能，但播放地址必须补 xeapi。** 扫码登录、喜欢列表、歌词，ncm-api-rs 不改源码就能用。取播放地址靠它自带的 eapi 只有大约一半成功，移植 SPlayer-Next 的 xeapi 后全部成功。

| 项目 | 结果 |
|---|---|
| ncm-api-rs 干净 debug 构建 | 3 分 47 秒，144 个 rlib |
| 扫码登录 | 用户实测成功 |
| `login_status` | 83～433 ms |
| `likelist` | 181～716 ms，约 3600 首 |
| 取地址，SDK 自带的 eapi | 有地址 **11/24**，其余报 400；平均 41～50 ms |
| 取地址，移植的 xeapi | 有地址 **24/24**；平均 52～69 ms |
| CDN 取前 1 KB | 206，41～156 ms |
| 歌词（抽样 120 首） | 接口报错 0；lrc 119 首，翻译 58 首，逐字 43 首，逐字翻译 38 首 |
| amll-lyric 解析逐字歌词 | 1895 行 → 1895 行，15832 字，没有丢行，debug 版共 21 ms |

账号是黑胶 VIP（vipType=11），4 种音质（standard、exhigh、lossless、hires）xeapi 都能拿到地址。

对正式实现的影响：

1. **取地址必须走 xeapi。** 移植好的代码在 `spikes/netease-api/probe/src/xeapi.rs`，约 350 行。eapi 报 400 的原因没有查，SPlayer-Next 也已改走 xeapi。
2. **amll-lyric 可以用**，ADR 0003 里歌词这一项的"待摸底"可以去掉，不用退到 ypm 的 `yrc.rs`。
3. **逐字歌词只覆盖约 36% 的歌**（43/120），界面必须能退回按行歌词。
4. **ncm-api-rs 不要整个搬进来。** 382 个接口干净构建要 3 分 47 秒，M1 只复制用到的约 15 个。
5. 接口要有重试和错误提示：SDK 的错误把响应体丢了，这次 400 只能看到 `Unknown error`。

没验证：

- T-1 的引擎放网易云的真实地址：声卡被用户的 SPlayer-Next 独占，`0x8889000A`。CDN 的 Range 请求是通的。
- 易盾 v3 token 和"喜欢"：这是写操作，实验没碰。
- reqwest 升到 0.13（ADR 0003 的要求）：实验用的是 0.12。
- Linux。
